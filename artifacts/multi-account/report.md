# 多账号功能实测报告

测试时间：2026-09-15（America/New_York；UTC 2026-09-16）。

结论：核心多账号权限与数据隔离在本轮实测中通过；发现 1 个失效空间的前端恢复问题，不能据此认定所有功能完全正常。建议公网部署前修复并复测该问题。

## 实测环境与方法

- 实际访问入口：`http://localhost:8081/api/v1`，经过当前前端 Nginx；后端为正在运行的 `WeKnora-app`，镜像标签 `wechatopenai/weknora-app:latest`，容器创建时间 2026-09-08。
- 创建 4 个独立测试账号、4 个工作空间（3 个个人空间、1 个协作空间）、1 个共享空间、2 个空知识库、1 个空对话和临时 API Key。账号统一使用 `qa0916022642.*@example.invalid`，未使用真实业务资料。
- 149 条 API / 数据断言记录全部通过，包含准备、正常路径、拒绝路径和清理，不等于 149 个独立业务场景。原始记录：`results.json`。
- 使用浏览器实际操作登录、切换空间、成员管理、发出站内邀请、退出、另一账号登录、接受邀请及切换至编辑角色空间。
- 未修改产品代码或运行配置，保留工作区原有未提交改动。

## 通过的功能

| 范围 | 实际验证 |
|---|---|
| 注册与空间 | 自助注册、自动个人空间、创建空间、所有者初始化；创建请求无法自定超大存储配额或禁用状态 |
| 空间隔离 | 未登录拒绝访问；外部账号不能查看空间设置、成员、邀请、密钥或审计；伪造 X-Tenant-ID 无法越权；禁止切换至未加入空间 |
| 角色 | viewer 不能写入或管理成员；contributor 可创建及修改自己的知识库，不能修改别人的；admin 可修改他人知识库和读取审计，但不能管理成员；owner 可管理成员 |
| 成员生命周期 | 邀请、重复邀请、接受、拒绝、撤销、直接添加、退出、移除、重新加入；升降权对旧令牌立即生效；退出或移除后旧令牌无法读取空间资源 |
| 所有权 | 最后一个 owner 不能退出、被删除或降级；增加第二个 owner 后允许转交；原 owner 降权后立即失去管理权限 |
| 邀请安全 | 他人不能代为接受；接受/拒绝/撤销后的邀请不能重放；链接注册加入指定空间且角色正确；访客拿不到邀请令牌；撤销链接后查询与注册均被拒绝 |
| 知识库 | 外部账号无法读取、修改或删除私有知识库，列表也不会暴露测试知识库 |
| 对话 | 同空间其他用户和其他空间用户均不能读取、修改、删除他人的对话，列表也不返回该对话 |
| 共享空间 | 邀请码加入、审批加入、待审批无权限、只读共享知识库、禁止只读方写入、移除与退出后失去权限、撤销共享 |
| API Key | retrieve 能力仅能访问指定知识库；无法访问其他知识库或管理成员；撤销后立即失效 |
| 会话 | 注销后 access token 与 refresh token 均失效；正常 refresh 成功，已轮换的 refresh token 不可重用 |
| 删除 | 测试空间、共享空间、知识库、对话可删除；已删除空间旧令牌返回 401；删除协作空间后仍可登录剩余个人空间 |

## 发现的问题：失效空间未正确退出前端界面（P2）

复现条件必须完整保留：测试成员在浏览器中处于协作空间；由 API 删除该协作空间，随后删除其个人空间，使该账号无剩余可用空间；刷新浏览器。

实际结果：页面仍停留在 `/platform/knowledge-bases`，左下角保留已删除的 `qa0916022642_shared` 和“编辑”角色；展开菜单后身份变成占位的“用户 / user@example.com”；出现“加载模型列表失败”，未进入登录页或无空间引导页。再次操作菜单仍可见残留状态。浏览器错误日志包括 `failed to load knowledge bases`、`Failed to list models`、`failed to load agents`。

预期结果：确认账号状态后进入空间选择/创建引导；若凭据失效则清理完整登录状态并进入登录页。不得用已删除空间及占位身份继续呈现业务页面。

影响：用户会卡在不可用页面；本轮未观察到数据越权，接口层已经拒绝访问。尚未独立复测“仅删除当前空间但保留个人空间”是否存在同样的界面问题，因此不把问题范围扩大到该条件。

定位线索（尚非修复验证）：`frontend/src/utils/request.ts:191` 的刷新失败路径只清理 token/user/tenant 等部分缓存，没有统一调用 auth store 的完整 logout 清理；`frontend/src/router/index.ts:349` 在缓存已呈现登录态时跳过重新获取身份。应检查失效响应、刷新重试、Pinia 状态与 selected-tenant/membership 缓存的同步。这次按测试范围只记录缺陷，未改产品代码或部署。

- 已通过 API 删除所有测试知识库、对话、共享空间与工作空间。
- 4 个测试账号已停用并软删除，42 条测试认证令牌已撤销；数据库验证活跃测试账号、空间、成员关系均为 0，见 `cleanup.txt`。
- 测试记录和软删除/审计数据保留；未物理清空审计记录。含测试密码的临时状态文件已删除，报告和结果不含令牌或密码。
- 未执行真实文档上传/下载、向量检索和模型问答，也未执行 OIDC、公网 HTTPS/反向代理、多副本、多浏览器标签同时刷新、高并发抢占最后 owner、邀请真实等待过期、密码找回或抗爆破/限流测试。这些不在本轮通过结论内。
- 当前注册配置为 `self_serve`；该记录是环境事实，不代表已评估公网开放注册的运营策略。
- 本机无 Go 工具链、前端无 node_modules，本轮未运行源码单元测试；主要证据来自已部署容器的真实 HTTP 响应与浏览器操作。
